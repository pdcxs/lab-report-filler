# Lab Report Filler

一个帮助你填写 Typst 实验报告的桌面应用，学生无需接触 Typst 源码。老师设计模板，学生只填姓名、学号、班级、地点和各实验记录，导出为规范的 PDF，文件名为 `{中文姓名} - {学号}.pdf`。

[English](README.md) | [中文](README.zh.md)

---

## 简介

Lab Report Filler 解决编程课中一个常见的问题：学生不熟悉 LaTeX/Typst 语法，用 Word 或 LaTeX 排版又参差不齐。这个应用让老师用一份 `lab.json` 定义实验结构（实验目的、内容、要求、校验规则），打包成 ZIP 分发给学生。学生打开 ZIP，填写文本框，点击**导出 PDF** 即可。

技术栈：**Tauri 2 + React + TypeScript + Mantine**，内置 Typst 编译器，学生除了这个应用不需要装任何东西。

## 功能

- 🎯 **零 Typst 门槛** —— 学生只会看到文本框和按钮。
- 🌐 **双语界面** —— 由 `lab.json` 里的 `language` 决定（`"zh"` 或 `"en"`）。
- 🌓 **亮/暗色主题** —— 跟随系统或手动切换。
- 🖼️ **友好的图片插入** —— 选图片，填标签和标题，应用自动把图片复制到 `images/` 并插入带标签的 `#figure(...)` 块。
- 💻 **代码块插入** —— 选语言，粘贴代码，填标题和标签。
- 🔗 **引用助手** —— 列出当前记录中所有带标签的图片和代码块，点击即可插入 `@label`。
- 📄 **实时预览** —— 停止输入 800ms 后重新编译，右侧实时渲染 SVG 页面。
- ✅ **导出前校验** —— 缺代码块、缺图、缺引用或文字太少会拦截导出并弹窗提示。
- 💾 **自动保存** —— 停止输入 800ms 后写入 JSON 文件。
- 🗂️ **目录记忆** —— 下次启动自动打开上次的实验目录。
- 👩‍🏫 **教师模式** —— 制作并预览实验模板，导出为 ZIP 分发给学生。

## 系统要求

- **Windows**：Windows 10 或更高版本。无需额外配置。
- **macOS**：macOS 11 或更高版本（提供 Apple Silicon 和 Intel 两个版本）。无需额外配置。
- **Linux**：主流发行版。**需要自行安装 Typst** —— 见下文。

### 在 Linux 上安装 Typst

本程序使用 [Typst](https://typst.app/) 编译器生成 PDF。Windows 和 macOS 版本内置了 Typst；**Linux 版本没有内置**，需要单独安装：


| 发行版 | 安装命令 |
|---|---|
| Arch Linux | `sudo pacman -S typst` |
| Ubuntu / Debian | `sudo apt install typst` |
| Fedora | `sudo dnf install typst` |
| openSUSE | `sudo zypper install typst` |
| 任何装了 Rust 的系统 | `cargo install typst-cli` |


如果发行版仓库里没有 `typst` 包，可以用 `cargo install typst-cli`（需要先装好 Rust）。安装完成后验证：

```bash
typst --version
```

## 安装

前往 [Releases](https://github.com/pdcxs/lab-report-filler/releases) 页面下载对应平台的安装包：

| 平台                            | 推荐安装包            |
| ------------------------------- | --------------------- |
| Windows                         | `.msi` 或 `.exe`      |
| macOS（Apple Silicon / M 系列） | `aarch64.dmg`         |
| macOS（Intel）                  | `x64.dmg`             |
| Linux                           | `.AppImage` 或 `.deb` |

**macOS 用户注意**：应用未做代码签名。首次打开时系统可能提示"来自身份不明的开发者"。右键点击应用 → **打开**，或在"系统设置 → 隐私与安全性"里手动允许。

## 学生使用说明

### 第一步 —— 获取实验包

老师会发给你一个 **ZIP 文件**（例如 `Java-Programming-Lab.zip`）。把它下载到电脑上。**不要**手动解压——应用会替你解压。

### 第二步 —— 选择学生身份

启动应用。欢迎页点击 **I am a Student / 我是学生**。

### 第三步 —— 打开 ZIP

有两种方式：

- 点击 **Open ZIP / 打开 ZIP**，然后选择你收到的 ZIP 文件。
- 或者把 ZIP 文件**直接拖入**应用窗口。

应用会弹窗要求你**选择一个空文件夹**，实验包会解压到那里。

**重要**：请选一个**空的**文件夹（比如在桌面新建一个叫 `JavaLab` 的文件夹）。如果文件夹里已经有东西，应用会提示你换一个。

### 第四步 —— 填写个人信息

在左侧面板填写：

- **Chinese Name / 中文姓名** —— 必须至少包含一个中文字符。
- **Student ID / 学号** —— 4–20 位字母或数字。
- **Class / 班级** —— 留空则使用老师设置的默认值。
- **Location / 实验地点** —— 留空则使用老师设置的默认值。

### 第五步 —— 逐个处理实验

用左侧列表切换实验。

右侧显示三个区域：

1. **实验目的和要求** —— 只读。
2. **实验内容** —— 只读。这是你的任务。
3. **实验记录应包含的内容** —— 只读提示。

这三个下方是**实验记录**编辑框，在这里写你的答案。

### 第六步 —— 撰写记录

编辑框上方有四个工具按钮：

- **Insert Code / 插入代码** —— 选语言，粘贴代码，填写标题和标签。应用会插入一个包含代码的 `#figure` 块。
- **Insert Image / 插入图片** —— 选截图，设置标签和标题。应用会把图片复制到项目里并插入带标签的 figure。
- **Insert Reference / 插入引用** —— 列出当前记录中所有带标签的图片和代码块。点击一条即可把 `@label` 插入到文本中。用它在正文里引用你的图片。
- **Show Example / 查看示例** —— 如果老师为该实验配置了示例内容，点击可查看。可以复制到编辑框修改。并非每个实验都有示例。

每个实验记录必须包含（校验规则）：

- 至少一个代码块。
- 至少一张图片。
- 正文中用 `@label` 引用该图片。
- 至少 50 个字符的文字说明（不含代码、图片和 Typst 命令）。

### 第七步 —— 预览

右侧面板会在你停止输入 800ms 后重新编译，显示实时 PDF 排版。

### 第八步 —— 检查与导出

点击右下角 **Validate / 检查**。如果缺东西，会弹窗精确告诉你缺什么。

校验通过后点击 **Export PDF / 导出 PDF**。PDF 会生成在项目文件夹中，名字是：

```
{中文姓名} - {学号}.pdf
```

也可以点击顶栏的 **Open Project Folder / 打开项目目录** 用系统文件管理器打开这个文件夹。

### 第九步 —— 提交

把 PDF 上传到课程提交系统。

### 小提示

- **自动保存**：停止输入 800ms 后自动保存。顶栏徽章会显示 **保存中…** 或 **已保存**。
- **切换项目**：要做另一个实验，点击顶栏的 **Open ZIP / 打开 ZIP**。
- **重新打开**：应用会记住上次的目录，下次启动自动打开。
- **看不到工具栏**：如果看不到工具按钮，确认你正处在**实验记录**编辑框（在只读面板下方）。

## 老师使用说明

### 第一步 —— 选择教师身份

启动应用，欢迎页点击 **I am a Teacher / 我是老师**。

### 第二步 —— 填写课程信息

填写：

- **课程名称** —— 课程标题，显示在封面上。
- **指导教师** —— 教师姓名，显示在封面上。
- **默认班级** —— 封面上的班级。学生可以覆盖。
- **默认实验地点** —— 封面上的实验地点。学生可以覆盖。
- **界面语言** —— `zh` 或 `en`。控制学生看到的界面语言。
- **代码语言列表** —— 每行一个。学生会在 **Insert Code** 下拉框里看到这些。

### 第三步 —— 配置学生字段

设置学生看到的姓名、学号、班级、地点的标签和提示文字。还可以配置：

- 姓名最小/最大长度。
- 姓名是否必须包含中文字符。
- 学号格式的正则表达式。

### 第四步 —— 添加实验

点击 **+ 添加实验** 添加实验。每个实验需要填写：

- **实验名称** —— 实验标题，显示在封面和实验页顶部。
- **实验目的和要求** —— Typst 源码。写 `+ 内容` 生成编号列表项，或写普通段落。
- **实验内容** —— Typst 源码。规则同上。
- **实验仪器和设备** —— 本实验使用的设备，例如"电脑"、"万用表"等。
- **记录指导** —— 每行一条。学生看到的 bullets 提示。
- **编辑框占位提示** —— 编辑框为空时显示的文字。
- **示例内容** —— 学生点击 **Show Example / 查看示例** 时显示的内容。可以留空。
- **校验规则** —— 每份学生记录必须包含什么（代码块、图片、图片引用、最少文字数）。

左侧实验列表可以拖动排序。

### 第五步 —— 预览

点击顶栏的 **打开预览**，可以看到完整报告的渲染效果。停止编辑 800ms 后自动刷新。

预览使用默认 logo。想看其他 logo，点击 **选择 Logo** 选一个图片文件。

### 第六步 —— 导出实验包

点击顶栏的 **导出 ZIP**。选择保存 ZIP 的位置。应用会：

1. 创建临时文件夹，包含：
   - `lab.json`
   - `utils/utils.typ`
   - `imgs/tyut-logo.jpg`（或你选的 logo）
2. 压缩成 ZIP 保存到你选择的位置。
3. 清理临时文件夹。

把 ZIP 分发给学生（学习平台、邮件、U 盘等）。

### 草稿持久化

你的编辑会自动保存到应用数据目录下的 `teacher-draft.json`。关闭再打开应用，未完成的工作会自动恢复。

想从头开始，点击顶栏的 **新建**。这会清空当前草稿并恢复空白模板。

### 自定义封面

默认的 `utils/utils.typ` 包含一个带太原理工大学校徽的封面。想换成其他学校的校徽：

1. 点击 **选择 Logo**，选择图片。
2. 无论原文件名是什么，都会被写入 ZIP 里的 `imgs/tyut-logo.jpg`。

要自定义封面排版本身，可以在导出后手动编辑 `utils/utils.typ`，然后重新打包。应用目前不支持在界面里编辑 `utils.typ`。

### 直接编辑 lab.json

如果需要编辑 `lab.json`（例如在 preamble 里加自定义 Typst 命令），解压导出的包，编辑文件，再重新打包即可。应用读取标准的 `lab.json` schema。

## 项目结构

解压后的实验包结构：

```
lab-folder/
├── lab.json                    # 课程配置 + 实验
├── images/                     # 学生插入的图片（自动创建）
├── utils/
│   └── utils.typ               # 封面模板
├── imgs/
│   └── tyut-logo.jpg           # 封面 logo
├── report-draft.json           # 学号未填时的学生数据
└── report-{studentId}.json     # 学号已填时的学生数据
```

导出后还会出现：

```
{中文姓名} - {学号}.pdf
```

## 开发

```bash
# 安装依赖
npm install

# 下载对应平台的 Typst sidecar
# 命名规则见 .github/workflows/release.yml
# 把二进制放到 src-tauri/binaries/

# 开发模式
npm run tauri dev

# 本地构建安装包
npm run tauri build
```

**技术栈**：Tauri 2、React 18、TypeScript、Mantine 7、Zustand。

## 发布

打 tag 触发 GitHub Actions。workflow 会为 Windows、macOS（Intel + ARM）、Linux 构建安装包并创建 draft release。

```bash
git tag v0.2.0
git push origin v0.2.0
```

然后去 GitHub Releases 页面检查 draft，确认无误后点 **Publish**。
